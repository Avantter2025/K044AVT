🎯 O que é a libK044AVT.so

A libK044AVT.so é uma biblioteca dinâmica Linux que permite que suas aplicações em C, C++, Java e Python se comuniquem com o dispositivo Avanttec TEC44AVT através da porta PS/2 de hardware da placa-mãe.

Componentes Controlados

📺 Display LCD HD44780 2 linhas × 40 colunas — escrita, posicionamento, limpeza
⌨️ Teclado Principal 44 teclas Leitura de eventos de tecla (make/break) com mapeamento ABNT2
⌨️ Teclado Auxiliar convencional Suporte a teclado PS/2 completo conectado à porta auxiliar
🔢 Teclado PIN 20 teclas Leitura segura de senhas com exibição em asteriscos
🔒 Módulo de Identificação Digital Sensor de impressão digital.
💡 Controle Status dos Leds Caps, Num e Scroll Lock

✅ Requisitos de Sistema

Hardware Necessário

  • Porta PS/2 física — conector roxo de teclado na placa-mãe
  • Teclado Avanttec TEC44AVT — conectado via cabo PS/2
  • ⚠️ Adaptadores USB-PS/2 passivos NÃO funcionam

Software Necessário

Requisito Especificação
Sistema Operacional Ubuntu 18.04 LTS ou superior (32-bit ou 64-bit)
Acesso root ou permissão sudo
Compilador/Runtime Dependendo da linguagem (C, C++, Java, Python)
Biblioteca de Acesso a Hardware libevdev-dev (para leitura de eventos)

🔧 Instalação de Ferramentas por Linguagem

Para C e C++

sudo apt-get update
sudo apt-get install -y gcc g++ make

# Verificar versões
gcc --version    # gcc 7.x ou superior
g++ --version
make --version

Para Java

Instale o JDK (Java 11 ou superior) e JNA para chamar bibliotecas C nativas:

sudo apt-get update
sudo apt-get install -y default-jdk

# Verificar instalação
java -version
javac -version

# JNA (Java Native Access) - opção recomendada
curl -L -o jna.jar \
  https://repo1.maven.org/maven2/net/java/dev/jna/jna/5.14.0/jna-5.14.0.jar
O que é JNA? É uma biblioteca Java que permite chamar funções de bibliotecas C nativas (como libK044AVT.so) diretamente a partir de código Java, sem necessidade de escrever código JNI em C.

Para Python

sudo apt-get update
sudo apt-get install -y python3

# Verificar
python3 --version   # Python 3.6 ou superior

# Python 3 inclui ctypes nativamente

📥 Instalação da Biblioteca libK044AVT.so

# Copiar para o diretório padrão do sistema
sudo cp libK044AVT.so /usr/local/lib/

# Registrar no cache de bibliotecas
sudo ldconfig

# Verificar instalação
ldconfig -p | grep K044AVT
# Saída esperada: libK044AVT.so => /usr/local/lib/libK044AVT.so

# Copiar headers (necessário apenas para C/C++)
sudo cp display_driver.h /usr/local/include/
sudo cp k044avt.hpp      /usr/local/include/
Importante: Se ldconfig -p | grep K044AVT não mostrar resultado, execute sudo ldconfig novamente.

🔴 Uso em C

Compilação

gcc -O2 -o meu_programa meu_programa.c \
    -L/usr/local/lib -lK044AVT \
    -Wl,-rpath,/usr/local/lib \
    -lpthread

sudo ./meu_programa

Exemplo Mínimo em C

#include "display_driver.h"
#include <stdio.h>
#include <unistd.h>

int main(void) {
    if (k044_open() != K044_OK) {
        fprintf(stderr, "Erro ao abrir dispositivo\n");
        return 1;
    }

    k044_clear();
    k044_write_line(0, "Ola, Mundo!");
    k044_set_cursor(1, 0);
    k044_write_string("C funcionando!");
    sleep(3);

    k044_clear();
    k044_close();
    return 0;
}

🔵 Uso em C++

Compilação

g++ -std=c++17 -O2 -o meu_programa meu_programa.cpp \
    -L/usr/local/lib -lK044AVT \
    -Wl,-rpath,/usr/local/lib \
    -lpthread

sudo ./meu_programa

Exemplo Mínimo em C++

#include "k044avt.hpp"
#include <iostream>
#include <thread>
#include <chrono>

int main() {
    try {
        avanttec::Display disp;  // RAII: abre e fecha automaticamente

        disp.clear()
            .setCursor(0, 0)
            .write("C++ funcionando!")
            .setCursor(1, 0)
            .write("K044AVT v1.0.0");

        std::this_thread::sleep_for(std::chrono::seconds(3));
        disp.clear();

    } catch (const avanttec::K044Error &e) {
        std::cerr << "Erro: " << e.what() << "\n";
        return 1;
    }
    return 0;
}

☕ Uso em Java

Compilação e Execução

# Com fat JAR (tudo incluído):
sudo java -cp k044avt-1.0.0.jar \
    -Djna.library.path=/usr/local/lib \
    com.avanttec.k044avt.exemplos.ExemploBasico

# Com arquivos separados:
javac -cp .:jna.jar K044AVT.java K044EventCallback.java \
      K044KeyEchoCallback.java K044KeyEchoCfg.java \
      K044Exception.java Display.java MeuPrograma.java

sudo java -cp .:jna.jar \
    -Djna.library.path=/usr/local/lib \
    MeuPrograma

Exemplo Mínimo em Java

import com.avanttec.k044avt.Display;
import com.avanttec.k044avt.K044Exception;

public class MeuPrograma {
    public static void main(String[] args) throws InterruptedException {
        try (Display d = new Display()) {
            d.clear()
             .setCursor(0, 0)
             .write("Java funcionando!")
             .setCursor(1, 0)
             .write("K044AVT v1.0.0");

            Thread.sleep(3000);
            d.clear();

        } catch (K044Exception e) {
            System.err.println("Erro: " + e.getMessage());
            System.exit(1);
        }
    }
}

Escrita no Display

Função Parâmetros Retorno Descrição

k044_write_buf(buf, len) uint8_t*, size_t int Escreve buffer de bytes.
k044_write_line(row, text) uint8_t row, const char* int Escreve linha inteira com padding de espaços.

Fingerprint (Identificação Digital)

Função Parâmetros Descrição
k044_fp_init() — Inicializa o módulo sensor de impressão digital.
k044_fp_get_image() — Captura uma imagem da impressão digital do sensor.
k044_fp_gen_char(buffer_id) uint8_t buffer_id (0 ou 1) Gera características/template a partir da imagem capturada.
k044_fp_match() — Compara duas características (buffer 0 vs. buffer 1), retorna score.
k044_fp_search(buffer_id, start_page, page_num, found_id) uint8_t, uint16_t, uint16_t, uint16_t* Busca uma característica no banco de dados, retorna ID encontrado.
k044_fp_reg_model() — Mescla dois buffers (características 0 e 1) em um modelo final.
k044_fp_store(buffer_id, page_id) uint8_t buffer_id, uint16_t page_id Armazena modelo (até 50 templates) no banco de dados do sensor.
k044_fp_load_char(buffer_id, page_id) uint8_t buffer_id, uint16_t page_id Carrega um template armazenado em um dos buffers.
k044_fp_delete_char(page_id, count) uint16_t page_id, uint16_t count Deleta um ou mais templates do banco de dados.
k044_fp_empty() — Limpa todo o banco de dados de templates (todos os usuários).
k044_fp_valid_template_count(count) uint16_t *count Retorna o número de templates válidos armazenados.
k044_fp_enroll(id, finger_timeout_ms) uint16_t id, int Alto nível: Orquestra enroll completo: aguarda dedo → captura → remove → captura novamente → mescla → armazena com ID. Recomendado para aplicações de UX.
k044_fp_search_retry(buffer_id, start_page, page_num, finger_timeout_ms, max_attempts, found_id) uint8_t, uint16_t, uint16_t, int, int, uint16_t* Alto nível: Busca com retry automático, aguarda dedo e compara. Mais simples que chamar `get_image()`/`gen_char()`/`search()` manualmente.
k044_fp_sleep() — Coloca o sensor em modo de economia de energia.
k044_fp_led_config(func, start_color, end_color, cycle_times) uint8_t, uint8_t, uint8_t, uint8_t Configura LED do sensor (cores, efeito de respiração/pulsação, ciclos).
k044_fp_set_callback(cb, userdata) k044_fp_callback_t, void* Registra callback de progresso para operações de enroll/search com retry (aguardando dedo, capturado, removendo dedo, mesclando, armazenando).
k044_fp_confirmation_str(code) int code Retorna string descritiva do erro/confirmação (ex: "Dedo muito leve", "Fingerprint não encontrada").
k044_fp_last_confirmation_code() — Retorna o último código de confirmação/erro da operação anterior.

Códigos de Retorno (Fingerprint)

Constante Valor Significado
K044_OK 0 Sucesso — operação completada.
K044_ERR_FP -8 Erro de sensor ou protocolo — use k044_fp_confirmation_str() e k044_fp_last_confirmation_code() para detalhes descritivos.
K044_ERR_FP_TIMEOUT -9 Timeout — operação aguardando dedo expirou (ex: `k044_fp_enroll`, `k044_fp_search_retry`).

📝 Reprogramação de Scancodes: Caso necessite alterar o scancode de qualquer uma dessas 44 teclas, use o aplicativo de programação de scancodes (k044-reprog-demo-1.0.0.jar). Este aplicativo lê, programa e compara a tabela diretamente na EEPROM do dispositivo. Não é possível reprogramar via libK044AVT.so — as funções de alto nível de teclado acessam a tabela em modo somente-leitura.

🔴 Códigos de Retorno

Constante Valor Significado
K044_OK 0 Sucesso — operação completada normalmente.
K044_ERR_PERM -1 Permissão negada — executar com sudo ou setcap cap_sys_rawio.
K044_ERR_TIMEOUT -2 Dispositivo não respondeu no prazo — verificar conexão PS/2.
K044_ERR_NODEV -3 Dispositivo não encontrado ou ID inesperado — verificar porta PS/2.
K044_ERR_RANGE -4 Parâmetro fora do intervalo válido — verificar limites de linha/coluna.
K044_ERR_INVAL -5 Parâmetro inválido — não passar NULL ou valores inválidos.
K044_ERR_BUSY -6 Recurso ocupado — event loop já ativo, aguarde antes de chamar novamente.
K044_ERR_RESEND -7 Dispositivo solicitou retransmissão após 3 tentativas — tentar novamente ou reiniciar.
Em Java e Python: Estes valores são retornados como inteiros normais ou lançados como exceção (K044Exception / K044Error).

⚠️ Limitações Conhecidas

Limitação Detalhes
Requer root / cap_sys_rawio Acesso direto a portas de hardware é restrito pelo Linux. Sem privilégios, a biblioteca não consegue ler/escrever na porta PS/2.
Coluna máxima: 15 Limitação do firmware do dispositivo (& 0x0F na decodificação). Display tem 40 colunas no total, mas a biblioteca limita a 16.
Apenas porta PS/2 física Adaptadores USB-PS/2 passivos não funcionam. É necessário uma porta PS/2 nativa na placa-mãe.
Um processo por vez O barramento PS/2 não é multiplexado. Apenas um programa pode usar a biblioteca por vez.
Módulos atkbd/psmouse conflitam Remover antes de usar: sudo modprobe -r atkbd psmouse.

🔧 Reiniciar o Controlador PS/2

Se o teclado parar de funcionar após alguns minutos de operação, o controlador PS/2 pode precisar ser reiniciado. Use este procedimento para recuperar a funcionalidade:

Sintoma

O aplicativo está rodando, mas deixa de responder aos eventos do teclado, embora o dispositivo ainda esteja conectado.

Solução

# Desabilitar o controlador
sudo bash -c 'echo -n "i8042" > /sys/bus/platform/drivers/i8042/unbind'

# Aguardar 2 segundos
sleep 2

# Reabilitar o controlador
sudo bash -c 'echo -n "i8042" > /sys/bus/platform/drivers/i8042/bind'

# Verificar o status
dmesg | tail -20
✅ Esperado: Mensagens no dmesg indicando i8042 reset e a detecção do teclado novamente. O aplicativo passará a responder novamente ao dispositivo.
⚠️ Aviso: Este procedimento reinicia o driver a nível do kernel. Durante alguns segundos, nenhum teclado ou mouse PS/2 responderá. Execute-o com segurança, garantindo que sua sessão não será desconectada.

📞 Suporte Técnico

Em caso de dúvidas ou problemas, contate o fabricante fornecendo as seguintes informações:

  • Versão do sistema operacional: lsb_release -a
  • Versão do kernel: uname -r
  • Descrição detalhada do problema e passos para reprodução
  • Mensagem de erro exata (copiar e colar completo)
Antes de contatar suporte:
  1. Verifique se a porta PS/2 está ativa na BIOS
  2. Reconecte o teclado
  3. Tente em outro computador ou com outro teclado
  4. Ative os logs de diagnóstico e capture a saída completa
