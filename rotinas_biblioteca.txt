Todas as rotinas retornam um int com um dos codigos abaixo, salvo indicacao
em contrario. K044_OK (0) sempre indica sucesso.

  K044_OK            0   sucesso
  K044_ERR_PERM     -1   permissao negada (requer root ou setcap CAP_SYS_RAWIO)
  K044_ERR_TIMEOUT  -2   dispositivo nao respondeu no prazo
  K044_ERR_NODEV    -3   dispositivo nao encontrado / ID invalido
  K044_ERR_RANGE    -4   parametro fora do intervalo valido
  K044_ERR_INVAL    -5   parametro invalido (NULL, etc.)
  K044_ERR_BUSY     -6   recurso ocupado (ex.: event loop ja ativo)
  K044_ERR_RESEND   -7   dispositivo solicitou retransmissao
  K044_ERR_FP       -8   erro do modulo fingerprint
  K044_ERR_FP_TIMEOUT -9 timeout aguardando o modulo fingerprint


-------------------------------------------------------------------------------
1. CICLO DE VIDA
-------------------------------------------------------------------------------

k044_open(void)
  Abre o dispositivo com configuracao padrao.
  Retorno: K044_OK ou erro

k044_open_ex(const k044_config_t *cfg)
  Abre o dispositivo com configuracao personalizada. cfg=NULL usa padrao.
  Retorno: K044_OK ou erro

k044_close(void)
  Fecha o dispositivo.
  Retorno: void

k044_lock(void)
  Captura o mutex do barramento PS/2.
  Retorno: K044_OK

k044_unlock(void)
  Libera o mutex capturado por k044_lock().
  Retorno: void

Diferenca entre k044_open() e k044_open_ex(): a primeira abre o dispositivo com a configuracao padrao (portas PS/2 0x60/0x64, timeouts padrao); a segunda abre com uma k044_config_t personalizada, util quando voce precisa mudar portas, timeouts ou nivel de log. Chame k044_config_init() para preencher os padroes e so altere o campo que precisar; k044_open_ex(NULL) equivale a k044_open().

Para que serve k044_lock/k044_unlock: garantem atomicidade quando voce precisa fazer varias chamadas seguidas sem que outra thread (ex.: a do event loop) intercale uma transacao PS/2 no meio. A maioria dos programas nunca precisa chama-los diretamente, pois as proprias rotinas da biblioteca ja usam o lock internamente quando fazem uma transacao composta.

Campos de k044_config_t (preenchidos por k044_config_init com os padroes, ajuste so o que precisar antes de chamar k044_open_ex): port_data/port_status sao os enderecos das portas de I/O do barramento PS/2 (padrao: 0x60/0x64) — so faria sentido mudar num hardware nao-padrao.
write_timeout_ms: quanto tempo esperar por confirmacao do dispositivo ao enviar um comando antes de desistir (padrao: 100ms).
read_timeout_ms: quanto tempo esperar por uma resposta/byte do dispositivo antes de desistir (padrao: 200ms).
reset_wait_ms: quanto tempo aguardar apos o comando de reset (0xFF) antes de continuar, dando tempo do firmware reinicializar (padrao: 1000ms).
max_retries: quantas vezes retransmitir automaticamente quando o dispositivo responde com K044_ERR_RESEND antes de desistir (padrao: 3).
log_level: verbosidade dos logs internos — K044_LOG_NONE, K044_LOG_ERROR, K044_LOG_WARN, K044_LOG_DEBUG ou K044_LOG_TRACE (padrao: K044_LOG_NONE).
Na pratica, os campos mais ajustados sao read_timeout_ms/write_timeout_ms (hardware mais lento que o normal, ex.: junto com o sensor de digital) e log_level (para depurar problemas de comunicacao); os demais quase nunca precisam mudar do padrao.

3. DISPLAY — ALTO NIVEL
-------------------------------------------------------------------------------

k044_write_cgram_preset(uint8_t pattern, uint8_t slot)
  Grava um padrao pre-definido (K044_CGRAM_PRESET_*) em um slot da CGRAM (0-7)
  Retorno: K044_OK ou erro

k044_write_char(uint8_t c)
  Escreve 1 byte na posicao atual do cursor. Bytes < 0x20 sao interpretados
  como comandos de controle (K044_BS, K044_CR, etc.).
  Retorno: K044_OK ou erro

k044_write_char_raw(uint8_t c)
  Escreve 1 byte direto na DDRAM, sem interpretar codigos de controle — usar
  para exibir caracteres CGRAM (codigos 0-7).
  Retorno: K044_OK ou erro

k044_write_string(const char *s)
  Escreve string terminada em '\0' (max 80 chars, duas linhas).
  Retorno: K044_OK ou erro

k044_write_buf(const uint8_t *buf, size_t len)
  Escreve um buffer de bytes no display.
  Retorno: K044_OK ou erro

k044_write_line(uint8_t row, const char *text)
  Escreve uma linha inteira (0 ou 1), completando com espacos ate a col 39.
  Retorno: K044_OK ou erro

k044_display_shift(int direction)
  Desloca o display inteiro (instrucao nativa do controlador HD44780)
  direction: [0] = esquerda,   [!= 0] = direita.
  Retorno: K044_OK ou erro

k044_write_display(const char *line1, const char *line2)
  Limpa o display e escreve as duas linhas de uma vez. NULL = linha vazia.
  Retorno: K044_OK ou erro

k044_write_pos(uint8_t row, uint8_t col, const char *fmt, ...)
  Escreve string formatada (estilo printf) na posicao (row, col).
  row: 0-1 | col: 0-39 | fmt/...: como printf.
  Retorno: K044_OK ou erro

k044_scroll_line(uint8_t row, const char *text, unsigned int delay_ms)
  Rola texto horizontalmente numa linha, um loop, janela deslizante.
  Retorno: K044_OK ou erro

k044_scroll_start(uint8_t row, uint8_t col_start, uint8_t width,
                   const char *text, unsigned int delay_ms, int repeat)
  Inicia scroll continuo em uma janela (col_start, width) da linha.
  repeat: 0 = loop infinito, N = numero de loops.
  Retorno: K044_OK ou erro

k044_scroll_stop(void)
  Para o scroll continuo iniciado por k044_scroll_start().
  Retorno: K044_OK ou erro

-------------------------------------------------------------------------------
7. MONTAGEM DE DISPOSITIVOS E LEITURA DE EVENTOS
-------------------------------------------------------------------------------

Esta secao orienta, de forma direta, como combinar as rotinas da
biblioteca de acordo com a arquitetura e os requisitos do seu aplicativo.
Abaixo sao apresentados a ordem correta das chamadas, os cenarios
tipicos de uso e a escolha do modo de leitura ideal.

📌 Cenarios Tipicos de Integracao

Cenario 1: Apenas Display/Cursor (Teclado inativo no sistema)
Objetivo: utilizar apenas a interface visual, sem que o teclado envie comandos para o sistema operacional.
Fluxo de Chamadas: k044_open() seguido estritamente pelas rotinas de controle de display/cursor. Nao inicialize uinput, mouse ou dispositivos auxiliares (aux).

Cenario 2: Terminal Interativo / Menu (Teclado ativo e funcional)
Objetivo: permitir que o usuario digite e navegue normalmente pelo sistema enquanto o software roda em segundo plano.
Fluxo de Chamadas: logo apos o k044_open(), chame a sequencia: k044_uinput_enable() -> k044_mouse_enable() -> k044_start_event_loop() -> k044_aux_enable() (caso haja teclado auxiliar fisico conectado).

Cenario 3: Teclado Bloqueado (Aguardando validacao/condicao)
Objetivo: reter a digitacao (ex.: travar o teclado ate que uma senha seja validada ou uma digital seja reconhecida).
Fluxo de Chamadas: execute apenas k044_open(). As teclas serao capturadas internamente pela biblioteca, mas nao serao injetadas no sistema operacional. Apos a validacao da condicao, libere o fluxo invocando as funcoes de inicializacao (uinput, mouse, aux e event_loop).

Cenario 4: Eco de Teclas no Display (Campos de texto / PIN)
Objetivo: mostrar os caracteres digitados diretamente na tela (ou asteriscos para senhas) de forma otimizada.
Fluxo de Chamadas: invoque diretamente k044_keyecho_start(). Esta funcao inicializa o laco de eventos (event loop) de forma autonoma se ele ainda nao estiver em execucao, dispensando a chamada manual de k044_start_event_loop().

Cenario 5: Ativacao Automatica do Mouse PS/2
Objetivo: garantir o funcionamento imediato e automatico do mouse desde a inicializacao do software.
Fluxo de Chamadas: chame obrigatoriamente k044_set_mouse_auto(1) antes de executar o k044_open(). Esse procedimento dispensa a ativacao manual posterior via k044_mouse_enable() ou k044_start_event_loop().

⚙️ Regra Geral sobre o Event Loop

A execucao do k044_start_event_loop() e obrigatoria para habilitar os seguintes recursos: traducao e injecao de teclas via subsistema uinput; recebimento de dados por leitura sincrona (k044_read_event()) ou assincrona (k044_set_event_callback()); e o funcionamento da rotina de eco em tela (keyecho).

⚠️ Atencao: as funcoes k044_read_event() e k044_keyecho_start() gerenciam e iniciam o event loop sozinhas se necessario. Contudo, a funcao k044_uinput_enable() NAO o inicia. Se voce habilitar o uinput sem disparar o event loop em algum momento, nenhuma tecla sera repassada ao sistema operacional.

🔀 Modos de Leitura de Evento — Qual usar?

  Modo                    Funcao base                Quando utilizar
  Callback (Assincrono)   k044_set_event_callback    Aplicacoes com interface
                                                      grafica (GUI) ou que
                                                      possuam um laco de
                                                      repeticao proprio que
                                                      nao pode ser bloqueado
                                                      aguardando a interacao
                                                      do usuario.
  Sincrono (Bloqueante)   k044_read_event            Programas de terminal
                                                      baseados em fluxos

                                                      (onde o sistema

🚨 Atencao ao Desempenho (Gargalo do Barramento)

Evite chamar rotinas manuais de display (como k044_write_pos, etc.) dentro de um loop de captura de eventos gerenciado por k044_read_event() ou pela funcao de callback. Como as operacoes de escrita no visor e o escaneamento do teclado compartilham o mesmo barramento fisico PS/2, cada transacao de tela concorrente causara atrasos perceptiveis (lag) na digitacao do usuario. Quando precisar exibir caracteres digitados no display, use sempre a funcao nativa k044_keyecho_start(), que implementa uma via de escrita otimizada para mitigar esse problema.

8. EVENTOS — Leitura Assincrona e Sincrona (event loop)
-------------------------------------------------------------------------------

O monitoramento de eventos permite que o programa seja notificado sobre
acoes dos dispositivos sem a necessidade de consulta constante (polling).
Existem dois modelos de implementacao, escolha conforme a arquitetura do
seu aplicativo:

  1. Modelo Assincrono via Callback
     Funcoes: k044_set_event_callback + k044_start_event_loop
     Funcionamento: o evento e disparado automaticamente em uma thread
     interna dedicada sempre que uma nova acao ocorre.
     Quando usar: ideal para aplicacoes com interface grafica (GUI) ou que
     possuam um loop principal proprio que nao pode ser bloqueado.
     Exemplo: um sistema de PDV (Frente de Caixa) que precisa continuar
     processando comandos na tela enquanto aguarda o cliente passar o
     cartao.
     Atencao: a funcao de callback deve ser leve, rapida e thread-safe
     (evite operacoes pesadas de I/O ou bloqueios).

  2. Modelo de Leitura Sincrona (Bloqueante)
     Funcao: k044_read_event
     Funcionamento: o programa executa um loop simples que bloqueia a
     execucao ate que o proximo evento ocorra ou o tempo limite (timeout)
     seja atingido.
     Quando usar: recomendado para aplicacoes de terminal (CLI) com fluxo
     sequencial, no estilo "espera o evento — processa — espera o
     proximo". E um modelo mais simples e linear de codificar do que o
     callback.

  Nota de encerramento: sempre chame a funcao k044_stop_event_loop()
  quando nao for mais necessario monitorar os perifericos, para liberar
  os recursos do sistema.

Tipos de Eventos Disponiveis (k044_event_type_t):

  Categoria    Evento(s)                  Descricao
  Teclado      K044_EVT_KEY_MAKE          Tecla pressionada
               K044_EVT_KEY_BREAK         Tecla solta
  PIN          K044_EVT_PIN_KEY           Digito do PIN inserido
  Cartao       K044_EVT_CARD_START        Eventos da leitura de cartao
               K044_EVT_CARD_DATA         magnetico (inicio, dado, fim,
               K044_EVT_CARD_END          erro)
               K044_EVT_CARD_ERROR
  Dados Puros  K044_EVT_RAW               Byte bruto do barramento PS/2

k044_set_event_callback(k044_event_cb_t cb, void *userdata)
  Registra callback chamado a cada evento (thread interna — deve ser rapido
  e thread-safe). NULL desregistra.
  Retorno: void

k044_start_event_loop(void)
  Inicia a thread interna de leitura de eventos (poll do PS/2 a cada 1ms).
  Retorno: K044_OK, ou K044_ERR_BUSY se ja ativo

k044_stop_event_loop(void)
  Para a thread de eventos.
  Retorno: K044_OK ou erro

k044_read_event(k044_event_t *evt, int timeout_ms)
  Leitura sincrona bloqueante de um evento (inicia o event loop se preciso).
  timeout_ms=0 = nao bloqueante.
  Retorno: K044_OK, ou K044_ERR_TIMEOUT se expirou

9. KEYECHO — EXIBICAO DE TECLAS NO DISPLAY
-------------------------------------------------------------------------------

k044_keyecho_cfg_init(k044_keyecho_cfg_t *cfg)
  Preenche cfg com valores padrao (row=0, max_chars=32, confirm=Enter, etc.).
  Retorno: void

k044_keyecho_start(const k044_keyecho_cfg_t *cfg, k044_keyecho_cb_t cb,
                    void *userdata)
  Inicia a exibicao de teclas pressionadas no display (so teclado principal).
  cfg=NULL usa padrao. cb=NULL = sem notificacao.
  Retorno: K044_OK, ou K044_ERR_RANGE se a config for invalida

k044_keyecho_stop(void)
  Para o keyecho e apaga a area usada no display.
  Retorno: K044_OK ou erro

k044_keyecho_get_buffer(char *buf, uint8_t *len)
  Copia o conteudo atual do buffer para buf (min. 16 bytes).
  Retorno: K044_OK, ou K044_ERR_INVAL se buf/len forem NULL

k044_keyecho_get_cursor(uint8_t *pos)
  Retorna a posicao do cursor dentro do buffer (0-based).
  Retorno: K044_OK, ou K044_ERR_INVAL se pos for NULL

k044_keyecho_clear(void)
  Limpa o buffer programaticamente (equivale a pressionar clear_scancode).
  Retorno: K044_OK ou erro

Campos de k044_keyecho_cfg_t (preenchidos por k044_keyecho_cfg_init, ajuste so o que precisar antes de chamar k044_keyecho_start): row/col_start/max_chars definem onde no display o texto aparece e ate onde ele pode crescer — atencao: col_start + max_chars deve ser <= 40, senao k044_keyecho_start retorna K044_ERR_RANGE.
clear_scancode e o codigo da tecla que limpa o buffer inteiro (0 = desativado).
confirm_scancode e o codigo da tecla que confirma a entrada e dispara o evento K044_KEYECHO_CONFIRMED (padrao: 0x5A = Enter).
pin_mode=1 mostra '*' em vez do caractere real (mesmo efeito visual do modo PIN, so que so no keyecho).
echo_enabled=0 mantem o buffer e o callback funcionando, mas para de escrever no display.

Para que servem os eventos k044_keyecho_event_t: sao os motivos pelos quais o callback passado a k044_keyecho_start() e chamado, cada vez que algo muda no buffer de digitacao.
K044_KEYECHO_CHAR: uma tecla normal foi digitada e adicionada ao buffer.
K044_KEYECHO_CLEARED: a tecla de limpeza (clear_scancode) foi pressionada.
K044_KEYECHO_BACKSPACE / K044_KEYECHO_DELETE: um caractere foi apagado do buffer (a esquerda do cursor ou na posicao atual).
K044_KEYECHO_CONFIRMED: a tecla de confirmacao (normalmente Enter) foi pressionada — e aqui que voce normalmente le o buffer e processa a entrada finalizada (ex.: validar um PIN, submeter um campo).
K044_KEYECHO_FULL: o buffer atingiu max_chars e uma nova tecla foi ignorada — util para avisar o usuario que o limite foi atingido.
Na pratica, a maioria dos programas so precisa tratar K044_KEYECHO_CONFIRMED (para pegar o resultado final) e talvez K044_KEYECHO_FULL (para dar feedback de limite excedido); os demais eventos existem para casos mais avancados de sincronizacao de estado.

10. MODULO DE IMPRESSAO DIGITAL (fingerprint)
-------------------------------------------------------------------------------

k044_fp_init(void)
  Inicializa a comunicacao com o modulo fingerprint. Nao requer configuracao
  adicional; chame uma vez apos k044_open(), antes de qualquer outra rotina
  k044_fp_*.
  Retorno: K044_OK ou erro

k044_fp_get_image(void)
  Captura a imagem da digital apoiada sobre o sensor no momento da chamada.
  E' sempre o primeiro passo de um cadastro/identificacao manual, chamada
  antes de k044_fp_gen_char().
  Retorno: K044_OK, ou K044_ERR_FP se o sensor estiver vazio (nenhum dedo) ou
  a leitura falhar

k044_fp_gen_char(uint8_t buffer_id)
  Gera o template (assinatura da digital) a partir da ultima imagem
  capturada por k044_fp_get_image(), e guarda no CharBuffer indicado.
  buffer_id: qual CharBuffer (memoria temporaria do sensor) recebe o
  template gerado — 1 ou 2. Um cadastro manual usa os dois buffers (uma
  leitura em cada) antes de mescla-los com k044_fp_reg_model().
  Retorno: K044_OK ou erro

k044_fp_match(void)
  Compara os templates atualmente guardados nos CharBuffers 1 e 2 entre si
  (nao contra o banco de dados) e informa se pertencem ao mesmo dedo.
  Retorno: K044_OK se os templates coincidem, K044_ERR_FP se nao

k044_fp_search(uint8_t buffer_id, uint16_t start_page, uint16_t page_num,
               uint16_t *found_id)
  Busca o template de um CharBuffer no banco de dados do modulo.
  buffer_id: qual CharBuffer contem o template a procurar — 1 ou 2.
  start_page: posicao inicial do banco a partir de onde a busca comeca
  (normalmente 0).
  page_num: quantas posicoes, a partir de start_page, devem ser
  varridas na busca (ex.: 1000 para cobrir todo o banco).
  found_id: ponteiro de saida — recebe o ID/posicao do template
  encontrado quando a busca tem sucesso.
  Retorno: K044_OK se encontrado, K044_ERR_FP se nao

k044_fp_reg_model(void)
  Mescla os templates guardados nos CharBuffers 1 e 2 em um unico modelo,
  pronto para ser gravado no banco com k044_fp_store(). Passo intermediario
  de um cadastro manual (entre gerar os templates das leituras e
  armazena-los).
  Retorno: K044_OK ou erro

k044_fp_store(uint8_t buffer_id, uint16_t page_id)
  Grava o modelo atualmente no CharBuffer indicado no banco de dados do
  modulo, numa posicao especifica.
  buffer_id: qual CharBuffer contem o modelo a gravar — 1 ou 2 (depois de
  chamar k044_fp_reg_model(), o modelo mesclado fica disponivel em ambos).
  page_id: posicao/ID no banco onde gravar (0-999) — e' o identificador
  que sera devolvido depois por k044_fp_search()/k044_fp_auto_identify().
  Retorno: K044_OK ou erro

k044_fp_load_char(uint8_t buffer_id, uint16_t page_id)
  Carrega um modelo ja gravado no banco de volta para um CharBuffer, para
  poder compara-lo (k044_fp_match()) com uma nova leitura.
  buffer_id: para qual CharBuffer carregar o modelo — 1 ou 2.
  page_id: de qual posicao do banco (0-999) carregar.
  Retorno: K044_OK ou erro

k044_fp_delete_char(uint16_t page_id, uint16_t count)
  Remove um ou mais templates do banco de dados.
  page_id: posicao inicial (0-999) a partir de onde remover.
  count: quantos registros consecutivos remover a partir de page_id
  (1 para apagar so aquela posicao).
  Retorno: K044_OK ou erro

k044_fp_empty(void)
  Limpa todo o banco de dados de templates do modulo — remove todos os
  cadastros de uma vez. Nao pode ser desfeito.
  Retorno: K044_OK ou erro

k044_fp_valid_template_count(uint16_t *count)
  Conta quantos templates validos existem no banco de dados no momento.
  count: ponteiro de saida — recebe o numero de templates encontrados.
  Retorno: K044_OK ou erro

k044_fp_led_off_fast(void)
k044_fp_led_on_fast(void)
k044_fp_led_flashing_fast(void)
k044_fp_led_breathing_fast(void)
  Ajustam o LED do sensor para um estado fixo (cor azul, ciclos=0) usando um
  comando pre-gravado no firmware, sem parametros — mais rapido e mais
  confiavel na transmissao do que k044_fp_led_config(), mas sempre na cor
  azul e sem possibilidade de transicao de cor. Use k044_fp_led_config()
  quando precisar de outra cor ou de uma transicao entre cores.
  Retorno: K044_OK ou erro (cada uma)

k044_fp_read_nfpage(k044_fp_nfpage_t *page)
  Le a pagina de informacoes do modulo (numero de registros, tamanho do
  banco, numero de serie, versao de firmware, fabricante, nome do sensor,
  etc.).
  page: ponteiro de saida (struct k044_fp_nfpage_t) que recebe os dados
  lidos; pode ser NULL se voce so quiser confirmar que o modulo responde,
  sem se importar com o conteudo.
  Retorno: K044_OK ou erro

k044_fp_sleep(void)
  Coloca o modulo em modo de baixo consumo. Qualquer rotina k044_fp_*
  chamada depois disso desperta o modulo automaticamente.
  Retorno: K044_OK ou erro

k044_fp_led_config(uint8_t func, uint8_t start_color, uint8_t end_color,
                    uint8_t cycle_times)
  Controla o LED do sensor de digital, com controle total sobre modo, cor(es)
  e numero de ciclos (ao contrario das rotinas k044_fp_led_*_fast(), que sao
  pre-fixadas em azul).
  func: modo do LED — uma das constantes K044_FP_LED_* (ver tabela no final
  desta secao).
  start_color: cor inicial — uma das constantes K044_FP_LED_COLOR_* (ver
  tabela no final desta secao).
  end_color: cor final — use o mesmo valor de start_color para uma cor
  solida, ou um valor diferente para fazer uma transicao entre as duas
  cores.
  cycle_times: numero de ciclos do efeito (0 = infinito, repete ate o
  proximo comando de LED).
  Retorno: K044_OK, ou K044_ERR_FP se o sensor rejeitar o comando

k044_fp_auto_identify(uint8_t score_level, int16_t id_number,
                       uint16_t *found_id, uint16_t *score)
  Identificacao automatica: captura a imagem, gera o template e busca no
  banco, tudo em um unico comando (equivalente a get_image+gen_char+search
  encadeados internamente).
  score_level: nivel de exigencia do match, de 1 (mais permissivo) a 9
  (mais rigoroso) — recomendado 5.
  id_number: -1 para buscar em todo o banco; ou um ID especifico (0-999)
  para verificar 1:1 apenas contra aquele registro.
  found_id: ponteiro de saida — recebe o ID encontrado.
  score: ponteiro de saida — recebe a pontuacao de confianca do match.
  Retorno: K044_OK se identificado, K044_ERR_FP se nao

k044_fp_auto_enroll(uint16_t id, uint8_t entries)
  Cadastro automatico multi-etapa: o proprio modulo guia o processo
  internamente (pedir o dedo, capturar, pedir de novo, mesclar e gravar),
  notificando o progresso via callback (veja k044_fp_set_callback()).
  id: identificador onde o cadastro sera gravado (1-999).
  entries: numero de leituras/amostras do dedo a realizar (1-3,
  recomendado 3, para maior precisao).
  Prefira k044_fp_enroll() como alternativa mais previsivel — ela reimplementa
  o mesmo fluxo chamando as rotinas basicas diretamente, sem depender do
  AutoEnroll interno do firmware.
  Retorno: K044_OK ou erro

k044_fp_set_callback(k044_fp_callback_t cb, void *userdata)
  Registra uma funcao de callback para acompanhar, em tempo real, o
  progresso de uma operacao demorada do fingerprint (cadastro ou busca) —
  util para dar feedback ao usuario (ex.: "coloque o dedo", "capturado,
  retire o dedo", "gravando...") sem precisar ficar consultando o estado
  manualmente.
  cb: ponteiro para uma funcao com a assinatura
  void (*)(int status, int step, void *userdata). NULL desregistra o
  callback atual. Os dois primeiros parametros recebidos por essa funcao,
  quando chamada pela biblioteca, significam:
    status — 0x00 quando o passo correspondente teve sucesso; qualquer
    outro valor e' um codigo de confirmacao do sensor (o mesmo tipo de
    codigo devolvido por k044_fp_last_confirmation_code()) — passe esse
    valor para k044_fp_confirmation_str() para obter uma descricao
    textual do que aconteceu.
    step — o passo atual da operacao em andamento. O significado depende
    de qual funcao disparou o callback:
      * k044_fp_enroll() e k044_fp_search_retry() (rotinas de alto nivel
        desta biblioteca): usam as constantes K044_FP_STEP_WAIT_FINGER (1),
        K044_FP_STEP_CAPTURED (2), K044_FP_STEP_REMOVE_FINGER (3),
        K044_FP_STEP_MERGING (4) e K044_FP_STEP_STORING (5).
      * k044_fp_auto_enroll() (processo interno do proprio firmware): usa
        uma numeracao propria do modulo (0=captura de imagem, 1=extracao
        de caracteristica, 2=gravacao, etc.) — nao ligada as constantes
        K044_FP_STEP_* acima.
  userdata: ponteiro opaco definido por voce, repassado sem alteracao a
  cada chamada do callback — use para identificar contexto (ex.: qual tela
  ou objeto da sua aplicacao disparou a operacao).
  Retorno: void

k044_fp_enroll(uint16_t id, int finger_timeout_ms)
  Cadastro manual em 3 leituras (encadeia GetImage+GenChar+RegModel+Store
  internamente), alternativa mais previsivel ao AutoEnroll do firmware
  (k044_fp_auto_enroll()). Reporta o progresso via callback, se registrado
  (veja k044_fp_set_callback()).
  id: identificador onde o cadastro sera gravado (1-999).
  finger_timeout_ms: tempo maximo de espera pelo dedo, em milissegundos,
  em cada uma das 3 capturas — se o tempo esgotar sem detectar o dedo, a
  funcao retorna K044_ERR_FP_TIMEOUT.
  Retorno: K044_OK, ou K044_ERR_FP/K044_ERR_FP_TIMEOUT

k044_fp_search_retry(uint8_t buffer_id, uint16_t start_page,
                      uint16_t page_num, int finger_timeout_ms,
                      int max_attempts, uint16_t *found_id)
  Identificacao com repeticao automatica: captura e busca no banco, e
  tenta de novo em caso de falha, ate max_attempts tentativas.
  buffer_id: qual CharBuffer usar internamente para gerar o template de
  cada tentativa — 1 ou 2.
  start_page: posicao inicial do banco a partir de onde a busca comeca.
  page_num: quantas posicoes, a partir de start_page, devem ser
  varridas em cada tentativa de busca.
  finger_timeout_ms: tempo maximo de espera pelo dedo, em milissegundos,
  em cada tentativa.
  max_attempts: numero maximo de tentativas de captura+busca antes de
  desistir.
  found_id: ponteiro de saida — recebe o ID encontrado, quando ha sucesso.
  Retorno: K044_OK se encontrou, K044_ERR_FP/K044_ERR_FP_TIMEOUT senao

k044_fp_confirmation_str(int code)
  Traduz um codigo de confirmacao do modulo em uma descricao textual legivel.
  code: o codigo a traduzir (0-53) — normalmente o valor recebido no
  parametro status de um callback (k044_fp_set_callback()) ou devolvido pela
  propria k044_fp_last_confirmation_code().
  Retorno: const char* (string estatica, nao precisa ser liberada)

k044_fp_last_confirmation_code(void)
  Retorna o ultimo codigo de confirmacao recebido de qualquer chamada
  k044_fp_* — use para detalhar uma falha reportada como K044_ERR_FP,
  passando o valor retornado para k044_fp_confirmation_str().
  Retorno: int (codigo, ou 0xFF se a resposta nao pode ser interpretada)

k044_fp_raw_test(const uint8_t *data, uint16_t data_len, uint8_t *resp,
                  uint16_t *resp_len, uint16_t max_resp)
  Diagnostico de baixo nivel: NAO usar para comunicacao normal com o
  modulo. Usado apenas para testar o sensor isoladamente, enviando um
  pacote bruto e observando a resposta crua.
  data: buffer com os bytes a enviar diretamente ao sensor.
  data_len: quantidade de bytes em data a enviar.
  resp: buffer de saida onde a resposta do sensor e' copiada.
  resp_len: ponteiro de saida — recebe a quantidade real de bytes
  recebidos na resposta.
  max_resp: capacidade do buffer resp, em bytes (limite maximo que pode
  ser copiado para ele).
  Retorno: K044_OK se o comando foi aceito e a transacao completou
